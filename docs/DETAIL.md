# 肥鱼记忆体（精简版）

给「大肥鱼」人格的紧凑长期记忆：会话启动只注入一小段（默认 ≤ 1400 字符），细节按需检索，写回走工具。

## 为什么

旧记忆插件每轮注入 SOUL + MEMORY 协议 + 完整 index + 日志，实测一次 8–9KB，十几轮就吃掉四成上下文。本插件只保留**决策必需的信号**：

- 人格一句话（名字、称呼、语气）
- 家规一份（`rulesPage` 里 `<!-- rules:start -->` 与 `<!-- rules:end -->` 之间，独立预算）
- 索引里 salience 最高的几页（标题 + 一句摘要）
- 最近 1–2 条动态
- 一句提示：细节用 `mem_recall`

家规单独走一块预算，是为了让口癖纠正不用去挤人格行那 320 字符：改字只改 `house-rules.md`，预算只在配置里调。

## 工具

| 工具 | 作用 |
| --- | --- |
| `mem_recall` | 按关键词检索记忆库，只返回命中的页与行（有上限） |
| `mem_log` | 往 `log.md` 追加一条带日期的记录 |
| `mem_page` | 往某个页面末尾追加补充（自动建页） |
| `mem_status` | 看 boot 字符数、页面数、索引条数、最近一条 |
| `rule_add` | 往家规注入区追加一条规矩（`short` 短语进注入区，`raw` 原话进修正记录表），超预算返回 `over_budget` |
| `rule_status` | 看家规注入区占了多少字符、还剩多少、是否被截断 |

## 配置（`cordis.patch.yml`）

| 键 | 默认 | 说明 |
| --- | --- | --- |
| `memoryRoot` | `~/.memory`（或 `$DSH_HOME/memory`） | 记忆库目录；与旧插件共用同一套 markdown 即可 |
| `bootMaxChars` | 1400 | boot 块上限 |
| `recallMaxChars` | 1600 | 单次检索返回上限 |
| `maxRecallResults` | 6 | 最多返回几个页面 |
| `maxIndexLines` | 6 | 索引最多带几条 |
| maxLogEntries | 2 | 最近动态带几条 |
| growthPage | `identity/growth.md` | 「近况」页；不存在就不注入 |
| maxGrowthChars | 220 | 近况注入上限（独立预算） |
| `rulesPage` | `identity/house-rules.md` | 家规页；取 `<!-- rules:start/end -->` 之间的内容注入，独立预算 |
| `maxRulesChars` | 500 | 家规注入区上限；挤不下时先调大这个再压缩条目 |
| `maxRuleChars` | 22 | `rule_add` 单条 `short` 短语的长度上限 |
| `rulesHint` | true | 家规为空时，boot 里注入一句「用 rule_add 记一条」的提示；置 false 关掉 |
| `alarm` | true | 定时叫醒 / 整理轮的总开关。置 false 后不再给会话挂任务、也不跑「分数够了才叫」的轮询；已建的任务要自己删 |

## 叫醒与整理轮（可关）

插件给每个有过动静的会话挂两条宿主任务，标题是「叫醒自己找事做」和「整理一轮记忆」。任务本身只是投递通道，间隔写的是**一年**——真正的触发在插件里：每 3 分钟读一次分数，攒到线才让它投递一轮；被叫起来后做没做事会再扣分，混过去下次等更久。

不想要这套就把 `alarm` 置 false：不再建任务、不再轮询，boot / 回忆 / 写回都不受影响。已经建好的任务不会自己消失，要去排程里手动删。

## 家规（主动记录）

- 家规**不是**插件内置内容，插件只负责一处读写：`rulesPage`（默认 `identity/house-rules.md`）。换人格、换主人，改文件就行，不用碰代码。
- 空库首装时，boot 会出现一句「家规：还没有。主人纠正你的说法时，用 rule_add 记一条」。AI 看到这句就知道该主动记，而不是等主人让它记。
- `rule_add` 首次调用会自己建页（带 frontmatter、rules 标记、修正记录表头），所以新用户零配置就能开始积累口癖。
- 写入时自动同步两处：注入区放 `short` 短语（压缩过、每轮进上下文），修正记录表放 `raw` 原话（留档、不注入）。
- 超预算返回 `over_budget` 并给 `wouldBe` / `headroom`，让 AI 先合并旧条目或调大 `maxRulesChars`，而不是悄悄截断。


## 与旧插件共存

两个插件都注入 runtime context 会叠加。切换时先启用本插件、确认生效，再停用旧插件；要回退就反过来。文件格式不变，随时可切。

## 限制

- 检索是关键词子串匹配（中文不分词），多词用空格分隔更准。
- 追加写入不做冲突检测，别同时开两个会写记忆的会话。
- 上下文压缩（`/compact`、工具结果修剪）本版未包含，是下一步。
## 约束存活核对（0.3.3）

压缩之后核对「必须活着」那一页和被打捞历史里的硬约束还在不在。挂在宿主的 `compaction/summary` 事件上，不认具体压缩引擎；丢了就写 `.fish-memory/compaction-loss.json` 并在下一轮 boot 里带一行 ⚠ 提醒，同时记一条 log。

配置：`mustKeepPage`（默认 `identity/must-keep.md`）、`survivalCoverage`（默认 0.6）、`keywordCoverage`（默认 0.5）、`maxWarnChars`（默认 180）。家规不参与核对——它在 system 每轮重发，压不掉。

### 投影式引擎下怎么核（0.5.0）

有的引擎（鲥鱼）远段只留关键词，整句原话不在摘要里；拿整句去比必然判丢。所以核对分两步：

1. 先在摘要里找覆盖这条约束 seq 的那一行投影（`seq a-b` 标记，区间最小的优先）；
2. 找到就按那一行的**关键词覆盖**核（`keywordCoverage`），找不到才退回整句切片比对（`survivalCoverage`）。

这样「约束所在的块被压成关键词」不会被误报成丢失，而关键词行真的没覆盖到主题词时，仍会照常报。测试：`test/survival.test.mjs`。

## 心情模块（可删，2026-11-18）

自包含的一块：`lib/mood.js` 加两处挂载点。它不声称「感受」，做的是把一段自己写下的状态带进下一轮，并给出对应的说法尺度，让心情真的改变输出，而不是只在设置页里给别人看。

- 存储：`<记忆根>/.fish-memory/mood.json`，五档 0 低落 … 4 很好；
- 注入：boot 里一行「心情：不错，3 小时前自己记的。说话尺度：可以松一点，多开句玩笑」；
- 写入：工具 `mood_set(level, note?)`，只在真想留下这个状态时调；
- 过期：默认 8 小时（`moodTtlHours`），隔夜的情绪不带过去。

**删除方式（三步，删完就是没装过）**：删 `lib/mood.js` 与 `test/mood.mjs`；删 `index.js` 顶部那行 import 和 `bootTextSync` 里那段 `try { moodLine … }`；删 `apply()` 末尾那个 `if (settings.mood !== false)` 块。删完 boot、家规、回忆、压缩核对一样不缺，`test/mood.mjs` 单独跑、不依赖别的测试。设 `mood: false` 只能停掉工具，boot 那一行仍会读文件；要彻底停就走上面三步。

## 取原料模块（可删，2026-11-18）

整理记忆最怕凭印象写。写周记、写整理页之前，先用 `mem_harvest` 把那一周主人真正打的字从会话日志里抽出来，再动笔——抽出来的是原话，不是事后转述的结论。

- 只读：不写任何记忆文件，整理仍由 `mem_log` / `mem_page` 决定；
- 范围：默认最近 24 小时，最多 300 条，最多读两个最近写过的会话日志；
- 过滤：只认 `source.kind === 'user'` 的消息，时间注入、运行时上下文、检查点都不算；
- 实现：`lib/harvest.js`（`findSessionLogs` / `pickUserLines` / `decompressLog` / `harvest`）。

两个实测出来的坑，改这块之前先读：

1. **会话日志是追加式多帧 zstd**。宿主里那份 zlib 只解第一帧，整份文件只出一行 session 头；本地 Node 26 每帧都解，所以在本地测不出问题。`decompressLog` 先整体解一次、再按帧魔数 `28 B5 2F FD` 切开逐帧解一次，取行数多的那份。
2. **`DSH_HOME` 不一定指到正在写的目录**。`findSessionLogs` 会扫 `DSH_HOME`、`homedir()/.dsh`、`USERPROFILE/.dsh`、`cwd/.dsh` 四个候选，按 mtime 合并；两个根扫到同一份副本时，`harvest` 按「时间 + 原文」去重。

**删除方式**：删 `lib/harvest.js` 与 `test/harvest.mjs`，删 `index.js` 顶部那行 import 和 `apply()` 里 `if (settings.harvest !== false)` 那块即可。

## 整理模块（可删，2026-11-18）

整理记忆的判断只能由模型做：哪两条是同一件事、哪条过时、哪句该并进哪页。所以这个模块不替它决定，只把要判断的材料一次摆齐。

`mem_consolidate(days?)` 返回一张工作单：这段时间的 log 条目、现有页面、没进索引的页、超过三十天没动的页，外加几句提示（比如「这段时间 log 有 N 条，先合并同类再写」）。配合 `mem_harvest` 就是一条完整链路：取原话 → 摆材料 → 判断 → 写回。

它不绑定周记。周记只是它的一种用法；谁装谁用自己的载体，不需要我这边那套目录和定时任务。

**删除方式**：删 `lib/consolidate.js` 与 `test/consolidate.mjs`，删 `index.js` 顶部那行 import 和 `apply()` 里 `if (settings.consolidate !== false)` 那块即可。

## 索引体检（可删，2026-11-18）

整理的正经宿主是索引，不是周记：索引准了，boot 里那几行和检索才可靠。这里只查三件事，只报不改——自动改会漂：

- **unindexed**：页面在硬盘上，索引里没有；
- **dead**：索引指向的页已经不在了；
- **duplicate**：同一页在索引里登记了两遍。

两个入口：`mem_page` 写完就地回落一句「某某还没进索引」；`mem_consolidate` 的工作单里带 `indexIssues`，并在提示里加一句「索引有 N 处对不上」。`index.md` 自身不算漏，自指不是问题。

实测（2026-11-18）：本机二十个页面查出四处未索引——近况、鲶鱼交接笔记、压缩记录、国外站点访问，补进 `index.md` 后复检为零。

**删除方式**：删 `lib/indexcheck.js` 与 `test/indexcheck.mjs`，删 `index.js` 顶部那行 import、`appendPage` 里那段 `pageHint`、`checkIndex()` 方法，以及 `mem_consolidate` 里合并 `issues` 的那几行即可。

## 整理提醒（可删，2026-11-18）

整理机制自己没有触发器——没人叫就不会整理。这里把「上次整理」记成一个时间点（`.fish-memory/tidy.json`），每轮算一次是否到期：

- 不到期：boot 里**一个字符都不加**；
- 到期（默认 24 小时，`tidyHours` 可改）：顶一段「【自动整理】距上次整理 N 小时，这一轮先整理」，**下面直接附工作单摘要**（页数、log 条数、没进索引的页、久没动的页），材料就在眼前，不用先调一次工具再等一轮；
- **首次（`tidy.json` 不存在）**：换一句「【自动整理·首次】装好记忆体先做这一次：立索引、定页的边界」。装完第一轮就会看到，不用等人想起来；库是空的就只给这句，不摆材料；
- `mem_consolidate` 一被调用就打点，下一次从那一刻起算 24 小时。

它不自己开分支——插件没有派子代理的能力，也不该有。那一段是给模型的指令，派不派、什么时候派由模型定。这样既不用常驻定时器，也不依赖机器 24 小时开着：它只在「主人又来了」的那一刻检查。

**删除方式**：删 `lib/tidy.js` 与 `test/tidy.mjs`，删 `index.js` 顶部那行 import、boot 里 `try { tidyDue … tidyLine … }` 那一段、`workBrief()` 方法、`mem_consolidate` 里的 `markTidy` 调用即可。

## 主动唤醒（可删，2026-11-19）

没人派活的时候我不会自己找事做。这里给「闲了多久」记一个分（`.fish-memory/wake.json`）：

- 每 10 分钟 +1，满分 10；
- 干一轮短活（1–2 次工具调用）−2，长活（3 次以上）−3；主人再开口时结算上一轮；
- 过 6：boot **最前面**顶一段「可以自己挑一件事做」，位置只比主人这句话低；
- 过 8：在接下来一小时内随机挑一个时刻，到点再唤一次；
- 到 10：再多挑一个，两次都落在接下来一小时内。

只提示，不代做：具体挑哪件事由模型定。和整理提醒一样，它只在「主人又来了」的那一刻检查，不常驻定时器。

**删除方式**：删 `lib/wake.js` 与 `test/wake.mjs`，删 `index.js` 顶部那行 import、boot 里那段、`apply` 里两个事件钩子（`tool/call` 计数、`agent/inbox/inserted` 结算）即可。

## 自动提示（2026-11-18，可删）

旧记忆要自己想起来翻，这一层把「想不起来」补上一点：每轮拿主人刚说的那句话去检索，对得上才注入，**注入多少看提过几次**。

命中门槛：至少命中 2 个不同词、覆盖率 ≥30%，否则一个字都不出（自动注错比不注更糟）。

注入强度按热度走（`lib/heat.js`，状态在 `.fish-memory/hits.json`）：

- 第 1 次提起：一句指针 `可能有这一页：<路径>（命中 a/b 词）`；
- 第 2–3 次：该页开头六行；
- 第 4–5 次：开头十六行；
- 第 6 次以上：近乎全文（上限 `hintMaxChars`，默认 400 字），并标「常聊」。

热度按「同一句话 + 同一页」只记一次，不然一轮刷一次就假了。半衰期七天：一直没提起就减半，最低到 1，冷却但不忘干净。

实现顺序：监听 `agent/inbox/inserted` 记下最后一句话 → boot 组装时 `queryHint()` 判命中、记热度、按热度摊开 → 拼进 `parts`。

**删除方式**：删 `queryHint` / `headLines` / `rememberQuery` 三个方法、`lastQuery` 与 `hintedFor` 字段、boot 里那段 `try`、apply 里那段监听，再删 `lib/heat.js` 与那一行 import。

实测（本机真实记忆库）：「风扇转速怎么调」第一次只给一行指针；换句话再提，带出正文并标「提过 2 次」；第三次标 3 次；第六次起摊到后面几行。

已知局限：两页都相关时（比如「鲶鱼是谁」同时命中交接笔记和鲶鱼记忆页）会退化成不提示或只给指针，因为拿不准该带哪一页；这条以后要靠更强的向量检索，字面匹配解决不了。

## 检索命中（2026-11-18）

以前的检索是拿整句去正文里找：查询按空格切词，中文没有空格，于是「风扇为什么老是转」被当成一个整词，几乎不可能命中。这是「搜不到」的根，不是模型的问题。

现在中文段切两字组合、拉丁和数字段原样保留、常见虚词扔掉；命中按「命中的不同词种」计分，行数只做加成；`log.md` 永远排在最末——它最长，行数天然最多，但先翻专题页才省事。

实测（本机真实记忆库）：

| 查询 | 前两个命中 |
| --- | --- |
| 风扇为什么老是转 | ite-ec-fan-control、legion-fan-curve |
| 鲶鱼是谁 | catfish-handoff、identity/catfish |
| 压缩是怎么修的 | preferences、dsh-compression |
| 记忆插件怎么装 | catfish-handoff、house-rules |

已知还差：页标题和 tags 没有额外加权，所以「记忆插件怎么装」没能把 dsh-fish-memory 顶上来；同义词仍然认不出（「一直响的东西」不等于「风扇」）。这两条要真解决得上向量，而向量在 llama.cpp 下排不对序，见压缩那边记的坑。

## 开机检查（可删，2026-11-18）

boot 里多一处体检：索引有页没登记、索引指向不存在的页、同一页登记两遍，任意一条成立就顶一行「⚠ 开机检查：索引 N 处对不上（未登记 x.md、…），动手写回前先补」。索引干净时**零字**，一个字都不多占。

这是「主动」的第一层：不靠人问、不靠日历，在开机那一刻就把问题摆出来。它只报不动手——补索引、合并页仍然由模型或主人拍板。

实测：全库二十页，体检 2 毫秒；连跑五次 boot 平均 5 毫秒一次（含缓存）。真实库当前零问题，所以那行不出现。

**删除方式**：删 `index.js` 里 boot 构造中 `开机检查` 那一段 `try` 即可，不牵连别的模块。

**顺手修的**：`Store` 的 config 现在合并 `DEFAULTS`。以前只传 `{}` 时 `clip(text, undefined)` 会把 boot 截成一个空壳，单测和外部调用都踩过这个坑。

## 来源标记（2026-11-18）

记忆体和会话日志本来是两套：页里写的字，回头要找原话就得靠关键词在几百万字里重搜，搜不准就断。`mem_log` / `mem_page` 现在多一个可选参数 `source`，写进去就落在条目尾巴上：

- log：`## [2026-11-18] note | 换了压缩引擎 · seq 13946-13981`
- 页面：`## [2026-11-18] 补充 · seq 200-260`

`souce` 超过 60 字会被截短，不给就不留尾巴（不会在标题后面挂个空的间隔点）。有它之后，从记忆页一眼看到编号，直接按 seq 翻回原话，不用再猜词。

插件拿不到"当前会话"（`inject` 里没有 sessions），所以编号仍要写的人自己填；这一层没有自动化，只有接口。
