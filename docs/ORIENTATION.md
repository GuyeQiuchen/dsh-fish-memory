# 设计取向（不是功能说明）

> 改代码前先读这一页。功能细节看 `DETAIL.md`，改动记录看 README 的「变更」。
> 这一页只回答三个问题：**它是什么、它故意不做什么、什么情况下该推翻现在的做法。**

---

## 1. 它是什么

**一个小而准的索引 + 取回通道，不是知识库。**

它只做三件事：

1. 每轮注入一小块（默认 ≤1400 字符）：人格、家规、索引、近况；
2. 需要时按关键词取回记忆页的命中行（`mem_recall`）；
3. 按 seq 取回会话原文（`mem_seq`），不依赖任何压缩引擎。

它的价值不在“记得多”，在**记得准、能核对**。

---

## 2. 它故意不做什么

| 不做 | 为什么 |
|---|---|
| 语义搜索 / 向量 | 本机零依赖是硬约束；而且语义相近、事实相反的两页它分不开（“预取已做”和“预取没做”） |
| 整页贴进上下文 | 页里无关内容会被当成证据，这是今天最容易骗到我的入口 |
| 自动注入正文（0.5.7 起关掉） | 实测提示 15 次、跟随 0 次——它解决不了“没想到”，只会占前缀缓存 |
| 改写旧记忆页 | 旧页里哪些是推断已无从查证，重写等于造假；只补新页 |
| 替我做决定 | 它只给指针和事实；选哪个方案、要不要做，是主人和我的事 |
| 常驻大段内容 | 每多 100 字，都是从当前任务里抢走的注意力 |

---

## 3. 关键取舍

| 取舍 | 选择 | 代价 |
|---|---|---|
| 准确 vs 覆盖 | 宁缺勿滥：命中门槛不满足就一个字不出 | 覆盖低，指代句（“那个预取呢”）不触发 |
| 短 vs 全 | 注入 ≤1400 字符，家规 ≤500 | 长内容靠取回，不靠常驻 |
| 确定性 vs 聪明 | 关键词匹配，不调模型 | 换个说法可能找不到 |
| 省事 vs 可控 | 不做自动改写、自动合并 | 库会慢慢变旧，靠人整理 |

---

## 4. 唤醒分数的语义（容易被误读）

分数 = **闲置度**，不是“努力值”。

- 每 10 分钟 +1，满分 7；
- 干一轮活扣 2–3 分；
- 所以**忙的时候它是 0，这是设计本意**，不是坏掉。

分数只决定三件事：boot 里顶不顶“可以自己挑一件事做”（≥3）、要不要多唤一次（≥5）、两次（=7）。

如果哪天要让“忙也攒分”，改的是语义，不是修 bug——先问主人。

---

## 5. 什么情况下该推翻

| 信号 | 说明 |
|---|---|
| 索引长期覆盖不到常用页 | 说明关键词匹配这条路到头了，才谈语义 |
| `mem_recall` 命中行经常不够用 | 说明该改返回结构，不是加检索 |
| 宿主提供官方记忆接口 | 优先接官方，不自己维护一套坐标 |
| 注入内容被证明会误导 | 先减内容，再谈换机制 |

## 6. 改之前问自己

1. 这条改动会不会增加每轮的常驻 token？
2. 写进去的结论能不能指回一条原文（seq）？
3. 会不会让我把旧记录当现状？
4. 失败时会不会静默（不报错、没日志）？
5. 旧数据能不能继续用（不重写旧页）？
6. 有没有测试钉住“不这么做会坏的”那条行为？
