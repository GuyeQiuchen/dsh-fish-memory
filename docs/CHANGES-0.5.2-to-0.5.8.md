# 记忆体改动说明：0.5.2 → 0.5.8（2026-11-22 ~ 11-23）

这一段是把「记忆怎么送到模型面前」和「写进去的东西能不能指回原文」两件事重做了一遍。方向变过一次，中途有一版被打回重做，下面按时间顺序写清楚改了什么、为什么改、怎么验的、留了什么没做。

---

## 一、起点：0.5.2 的问题

0.5.2 的自动提示（`queryHint`）做的是：拿最近一条用户消息去检索记忆页，命中就把**几行正文**注入系统提示。

两个毛病：

1. **门槛太硬**：要求「命中 ≥2 个不同词，且命中率 ≥30%」。中文一句能切出几十个二元组，命中率天然极低；实测这条会话两天只触发 7 次，等于不存在；
2. **贴正文是错的**：注入的句子会被模型当成当前问题的一部分。主人报过：「他会因为一行摘要误会我问他的问题」。

---

## 二、0.5.3（做了，没留）

**改了什么**：把「相关」的判断从二元组命中率换成「具体信号」——ASCII 型号/文件名（≥3 字且非每页都有）、中文三字连续片段（剔除含虚词的片段）、短查询的两个稀有二元组；强命中贴带行号的原文，弱命中只给一行「去 mem_recall 核对」；同一页 3 轮冷却。

**为什么**：想解决「指代句和换说法检索不到」。

**结果**：用 351 条真实消息回放——贴原文 13.1%、只提醒 22.9%、回指未命中 3%。覆盖上去了，但**噪音同步上去**；而且它建立在 0.5.2 之外的一堆新判断上。

**为什么没留**：主人要求改动必须基于 0.5.2 原版做，不要在当前版本上继续叠。0.5.3 整个作废，代码没进任何包。

---

## 三、0.5.4：只做一件事——提示从「贴正文」改成「页 + seq」

**改了什么**

- `queryHint` 不再返回正文，只返回一行：

  ```
  · 记过这件事的页：projects/dsh-plugins.md，seq 10740-10770（命中 4/6 词）；原文用 mem_seq 按这个 seq 取回
  ```

- 新增 `seqNear(rel, terms)`：从命中行往上 8 行找最近的 `seq A-B`；
- 判断门槛、去重、热度、压缩后重给一次，全部保持 0.5.2 原样。

**为什么**

鲫鱼的检查点里，每个块本来就带 `[块 seq a-b]` 和「原文按 seq 取回」。记忆体再贴一段正文，等于给同一件事第二套坐标（页 vs 块），模型还得猜信哪边。**只回答「哪一页记过」，原文一律按 seq 取**，两条通路合成一条。

**怎么验的**

- 新增 `test/pointer.mjs`：给页+seq、不贴正文、同页同 seq 不重复、压缩后重给一次；
- 真实 360 条消息回放：命中 7.2%（26 条），其中带 seq 14 条、退回 `mem_recall` 12 条。

**已知代价**

覆盖率从 0.5.3 的 35% 掉回 7.2%。这是「回到 0.5.2 门槛」的直接结果：宁少不错。

**顺带发现**

10 个记忆页里只有 2 处写了 seq。链路设计成「页 → seq → 原文」，但大多数页没有 seq，实际只能退回 `mem_recall`。

---

## 四、0.5.5：取回自带，不再依赖压缩插件

**改了什么**

- 新增 `lib/seqread.js` 和工具 `mem_seq(from, to, session)`：直接读宿主会话日志（`.jsonl.zstd` / `.jsonl` 都认），按 seq 区间取回用户消息、助手消息、工具调用与结果；
- 写页时 `source` 含 seq，**自动补上会话 id**；
- 提示行改为「页 + seq + 会话」，指向 `mem_seq`。

**为什么**

主人问了一句关键的话：*「如果改成 seq，那么一旦压缩机制不是鲫鱼呢」*。

原来的取回借的是鲫鱼的 `jiyu_recall`。可 seq 是**宿主会话日志**的事件编号，不是鲫鱼给的：换成 basic、vcc、或者干脆不压缩，seq 照样存在。所以取回必须自己带。

还有一个隐蔽的坑：**seq 是按会话编号的**。同一个数字在别的对话里是别的内容，页里只写 seq 不写会话，换会话就指到无关内容——比没有指针更糟。

**怎么验的**

- 新增 `test/seqread.mjs`：按会话前缀找日志、区间取回、区间外不出现、区间过大拒绝、找不到会话明说；
- 新增 `test/tools.mjs`：真的 `apply()` 一遍、拿到工具定义、**调用** `mem_seq`。

**这一版出过一次事故**

第一次装上去，`mem_seq` 直接报 `readSeqRange is not defined`——工具加了，`import` 漏了。原来的单测只测 `lib/`，没测工具这一层，所以全绿也照样坏。补 `import` 之后加了 `test/tools.mjs`，缺 import 会在测试里炸，不会等到线上点它才发现。

## 五、0.5.6：修 `mem_status` 的「最近」

**改了什么**

```diff
- recentLog: log[0] ?? '',
+ recentLog: log[log.length - 1] ?? '',
```

**为什么**

0.5.2 退回时把这处小修一起带回去了（那是当时的决定，不是新 bug）。`logLines()` 按文件顺序返回，新的在后，取 `[0]` 拿到的是**倒数第二条**。写完一条立刻 `mem_status` 核对，会看不到，然后重复写一条。

**怎么验的**

新增 `test/status.mjs`：写三条 log，断言「最近」是第三条、不是第二条。

---

## 六、0.5.7：自动提示默认关闭

**改了什么**

- 配置新增 `autoHint`，默认 `false`；只有显式设 `true` 才注入提示行；
- 提示相关代码全部保留，配置打开就回来。

**为什么**

线上度量：**自动提示 15 次，其中 0 次真去读、36 次没人碰**。

提示注入了，模型一次都没顺着它去取原文——发了等于没发。主人原话：*「这句话塞进去像搞笑的，你根本不管」*。

留着还有四个真实成本：

1. 提示拼在系统提示里，每轮变一次，**前缀缓存每轮失效**；
2. 门槛只认词不认意思，**指错页会把模型带偏**；
3. 知道「有自动提示」会让人偷懒不主动查；
4. `hintIdle` 一直涨，度量线变噪声。

**怎么验的**

新增 `test/autohintoff.mjs`：默认不注入、显式 `autoHint: true` 才注入。

## 七、最终状态（0.5.7）

| 能力 | 状态 |
|---|---|
| `mem_recall(query)` 关键词检索 | 保留，未改 |
| `mem_seq(from,to,session)` 按 seq 取原文 | 新增，自带，不依赖压缩引擎 |
| 自动提示（往上下文顶一行） | 代码保留，**默认关闭** |
| 页里 seq 自动补会话 id | 新增 |
| `mem_status.recentLog` | 修正为最后一条 |
| 测试 | 32 项，全过 |

**已知边界（没解决，写清楚）**

- 页里 seq 覆盖率低（10 页 2 处），指针多半只能退回 `mem_recall`；
- 指代句（「那个预取呢」）**不触发**任何提示——这是 0.5.2 门槛的固有限制，不是 bug；
- 旧页的 seq 没有会话 id，跨会话不保证指对（新写的页会自动带）。

**没有做的事**

- 没有引入向量检索：它解决的是「换说法」，解决不了「指代」；而且会把「语义相近但事实相反」的记录判成相关；
- 没有把记忆页改成只存一条事实 + seq（讨论过，属于结构性改动，另起）。

---

## 八、0.5.8：写页必须带来源

**改了什么**：`mem_page` 的 `source` 从「可选」变成「必填」，且内容必须能看出 seq。

三种结果：

| 传入 | 结果 |
|---|---|
| `seq 12030-12145` | 正常写，行尾带来源 |
| `无 seq：长期观察` | 允许写（诚实声明） |
| 空着，或写了段话但里面没有 seq | **拒绝**，返回填写指引 |

**为什么**：11-23 的实测发现，10 个记忆页里只有 4 页写了 seq。没有 seq 的页 = 结论还在、原文指不回去；按「能拿回来才算设计成立」这条判据，这属于**真拿不回来**。

**为什么不给旧页补**：补 seq 等于给旧结论补证据，而按印象补很可能指错原文——指错比没有更糟。旧的 6 页就按低信任处理，新页从这一版起必须带。

**怎么验的**：

- 新增 `test/pagesource.mjs`：空来源被拒、非 seq 被拒、带 seq 能写、`无 seq：原因` 能写、写进去的页带来源行；
- 全量测试 33/33 通过；
- 装到 profile 后单独验过：无来源 `rejected`、带 seq `ok`。

**代价**：写页多一个参数，写的时候要记着 seq 区间；确实没有 seq 的场景需要显式声明，不能偷偷省略。

---

## 九、最终状态（0.5.8）

| 能力 | 状态 |
|---|---|
| `mem_recall(query)` 关键词检索 | 保留，未改 |
| `mem_seq(from,to,session)` 按 seq 取原文 | 自带，不依赖压缩引擎 |
| 自动提示（往上下文顶一行） | 代码保留，**默认关闭** |
| 写页来源 | **必填**（seq 或「无 seq：原因」） |
| 页里 seq 自动补会话 id | 有 |
| `mem_status.recentLog` | 取最后一条 |
| 设计取向页 | `docs/ORIENTATION.md`（新增，改代码前先读） |
| 测试 | 33 项，全过 |

**已知边界**

- 旧页 6/10 没有 seq，**不再补**，按低信任处理；
- 按标题找不到页（实测 3/6）：「主人」找不到主人页、「近况」返回空——`title:` 被当噪声过滤，待修；
- 指代句（「那个预取呢」）仍不触发任何提示；
- 不做语义/向量检索：换说法找不到是它的固有上限。

**顺带修的一处文档错误（11-23）**

`DETAIL.md` 里唤醒分数写的是「满分 10、过 6、过 8」，代码实际是 **7 / 3 / 5**，已改齐；并补了一句「这一轮结束时结算一次，不是每个工具扣一次」。
