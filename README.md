# 肥鱼记忆体（精简版）

给 DeepSeek Harness 的一条会记事的鱼：新开一个对话，它不用从零认识你。

## 它解决什么

新开一个对话，AI 就失忆了。不是它笨，是它每次只记得眼前这一小段。

这个插件给 AI 配一个记事本，放在你自己电脑的 `$DSH_HOME/memory`（通常是 `~/.dsh/memory`）里，记着你的习惯、你定的规矩、最近在忙什么。每次开口前翻一页看看，换个新会话也能接上话。

跟别的记忆插件比，它最大的好处是省：老办法一次塞八九千字，聊十几轮就占掉 AI 四成脑子；它只塞一千字左右，其余留在硬盘上，要用时再去翻。

## 装上之后，你会先收到两样东西

这个包不是空壳，它带了一副示例人设和一个主动唤醒机制。两样都可以关，但你在装之前该知道。

**默认人设**：开机块最前面那几行——名字、怎么称呼你、说话风格——是示例，写死在插件里。它能用，但不是你挑的。装上后 AI 会读到自己有一副性格，可能会照它说话。

**主动唤醒**：插件按时间给「主动做事」攒分，够了会在对话安静下来时叫醒 AI 一轮，让它自己挑一件事做。也就是说，你不说话的时候，它也可能自己起来。

插件会在新记忆库里留一封 `identity/welcome.md`，把这些写给 AI 看，让 AI 先问你这两样要不要留。别等它问——你直接说也行。

关掉的办法：人设改 `SOUL.md` 和 `identity/house-rules.md`；主动唤醒把配置里的 `alarm` 设成 `false`。

## 怎么用

装好之后什么都不用配。第一次跑，AI 的背景里会多一行提示：「家规：还没有，主人纠正你时记一条」。它不一定会主动跟你说这句，但你说过的规矩，它会默默记下。

你纠正它一次，比如「以后别在句尾加后缀」，它就把这条写进家规；原话进修正记录，短句进每轮注入区。下次开新会话，这条规矩已经在里面了。

家规有自己的一份字数预算，不会跟人格抢位置。装的人自己长自己的内容，这个包本身是空的。

## 怎么装

```sh
# Windows
.\install.ps1

# macOS / Linux
./install.sh
```

脚本会把包**复制**进 profile 的 `node_modules`，同时在 profile 自己的 `local-packages/` 里留一份副本（依赖指向这份副本，所以你下载的目录之后可以删掉、挪走）。改之前两份文件都带时间戳备份。装完重启 DSH。

用别的 profile 名：`.\install.ps1 -Profile other` 或 `PROFILE=other ./install.sh`。

**必须是真目录，不能是符号链接。** 宿主只为物理住在 profile 里的包解析 `@deepseek-ai/*`；链接能加载，但插件可能静默不激活。又因为依赖写成 `link:`，pnpm 下次装任何插件都会把它改回链接——所以之后再装插件，重跑一次这个脚本。

卸载：`.\uninstall.ps1` 或 `./uninstall.sh`。

第一次启动时，如果记忆根是空的，它会自己铺出目录、索引、`SOUL.md`、家规和近况，并留一封给 AI 的信。

## 跟压缩插件怎么配合

对话长了要压缩，压缩会把旧聊天变成一段摘要。你交代过的硬话——「别动那个文件」「以后先查再答」——很可能就跟着被压掉了，而 AI 自己不会察觉。

这个插件在压缩后回头核对：被压掉的那段里你说过的要求，摘要里还剩几条。少了的，下一轮开头直接摆在它眼前，写明「这几条可能没保住，先确认再干活」。同一条警告反复出现时，会在后面标次数，不重复刷屏。

别的记忆插件一般只做前半截，把东西塞进去；压完还有人回头核对一句，是它和压缩插件搭档的那半边。

## 它能做什么

- 每轮注入一页短文：你是谁、它的名字、你的规矩、它最近的近况、记忆索引、最近两条日志
- 你说一句规矩，它自己记下，不用重开对话；家规注入区和修正记录表由 `rule_add` 一起写
- 需要旧事时按关键词翻页，不把整库都塞进上下文
- 压缩之后核对约束有没有被压丢，丢了在下一轮开头报警

## 它做不到什么

- 不联网，所有内容只在你本机
- 不做语义搜索，关键词匹配，中文不分词，多个词用空格分开更准
- 不替你整理记忆，写什么、写多细，还是靠你和它
- 同时开两个会话往里写会打架，它没有锁

## 来源

这个包不是从零开始的。

磁盘上那套结构——`SOUL.md`、`MEMORY.md`、`BOOTSTRAP.md`、`index.md`、`log.md` 和分类目录——来自 [dsh-plugin-memory](https://github.com/LittleBlackTong/dsh-plugin-memory)（MIT，作者 LittleBlackTong）。它先把「记忆库该长什么样」立了下来。

这里把实现重写了：开机注入层、家规独立预算、压缩后核对、心情、整理提醒、取原料、自动补索引、主动唤醒，都是新代码。除了沿用那套文件约定，没有逐字搬过来的文件。

两边的差别在注入量：上游每轮把整套协议和索引注入进去，聊十几轮就吃掉四成上下文；这里只注入决策要用的那一小段，其余留在硬盘上按需翻。

## 变更

- **0.5.9（2026-11-23）**：两件事。
  - **默认人格只剩一句**：`CORE_PERSONA` 原来是一整段现成人设（鱼、白饭、语气、口头禅），现在只留「长成自己想要的样子」。插件不再替任何一只鱼规定性格——理由很直接：焊在代码里意味着每只鱼都是同一副，而且谁改自己的、一同步就改到所有人身上。规矩仍在 house-rules.md，名字称呼仍在 SOUL.md。代价是新库开机块里没有现成性格，得自己长。`test/guard.mjs` 跟着改断言。
  - **修 `mem_seq` 读不到多帧日志**：宿主的会话日志是**多帧** zstd（每写一批 flush 一帧），而 `zlib.zstdDecompressSync` 和流式解压**都只解第一帧**——37 MB 的日志解出 188 字节，于是「区间里没有事件」，还不报错。更阴的是原来先试整段解、解出带换行就当成功，那一帧里有换行，逐帧那条路一次都没走到。现在按帧格式自己算边界（`zstdFrames`），多帧就逐帧解；解压失败不再静默返回空，会说明是哪一步坏的。我这种会话上实测：44,026 条事件全部可读，随机抽 30 个位置取回 29/30（失败那个区间本来就没有可提取文本）。新增多帧单测——原来那组全用明文单帧，线上坏了测试照样全绿。
- **0.5.7（2026-11-22）**：自动提示默认关闭（`autoHint: false`）。线上度量是「自动提示 15 次、0 次真去读」，注入了没人用，等于噪声；要试就把它设 `true`。提示相关代码都保留，配置打开就回来。新增 `test/autohintoff.mjs`。
- **0.5.6（2026-11-22）**：`mem_status` 的「最近」改回取最后一条。0.5.2 退回时把 `log[0]` 一并带回来了，拿到的是倒数第二条——写完一条立刻核对会以为没写进去，然后重复写。新增 `test/status.mjs` 钉住。其余与 0.5.5 相同。
- **0.5.5（2026-11-22）**：取回自带，不依赖压缩插件。新增 `mem_seq(from,to,session)`，直接读宿主会话日志按 seq 区间取原文（zstd/jsonl 都认）；记忆页写 `source` 含 seq 时自动补上会话 id（seq 是会话内编号，不带会话会指到别的对话）；提示行改为「页 + seq + 会话」并指向 `mem_seq`。这样压缩引擎换 basic / vcc / 不压缩，取回仍然可用。
- **0.5.4（2026-11-22）**：自动提示改成「页指针 + seq」。原来命中就贴一段正文，可鲫鱼的检查点里每个块已经带 `[块 seq a-b]` 和「原文按 seq 取回」——同一件事两套坐标，模型还得猜信哪边。现在只回答「哪一页记过这件事」，原文走 `jiyu_recall`；页里没有 seq 才退回 `mem_recall`。压缩后仍会重给一次（那段历史被折掉了）；同一页同一 seq 不重复。判断门槛和 0.5.2 一致，没有动检索逻辑。
- **0.5.2（2026-11-22）**：审计后修一批真问题——索引死链在「目录读不到」时会误删（改为扫不全只补不删，并留 `index.md.bak`）；索引按 salience 排序方向反了；boot 的「最近」取成倒数第二条；`pendingHint` 未初始化导致空转计数；约束核对读 `session.events`（宿主没这个属性）改为 `snapshotEvents()`；`inject` 去掉硬依赖 `schedule`，没装 schedule 的 profile 也能加载；`mem_page` 拒绝写 index/log/SOUL 等结构文件；`schedule.run` 只认 id（改正文要先 `edit`）、返回值要检查；`install.ps1` 与 `install.sh` 对齐（不再重复插条目、没有 patch 文件也能装）；冒烟测试改用临时目录，不再写真实记忆根。

## 隐私

包里没有别人的记忆。装上去看到的一句兜底提示和几个工具，剩下的全由你本地的文件长出来。
